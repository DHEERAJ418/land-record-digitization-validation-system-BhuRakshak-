2026-10-05 requested fixes
---------------------------
- Administrator login now uses two-factor verification: password + registered-mobile OTP after CAPTCHA.
- Signup still verifies both phone and email OTPs, and after successful signup the user is redirected to the Login screen.
- Removed the Record View Password field from the user land-record form and removed the verification dependency on that password.
- Added Applicant Aadhaar Number to User Information. The submitted 12-digit number is validated but only its last four digits are retained; the full Aadhaar number is not stored or exposed.
- Public verified-record viewing no longer asks for a record password.
- QR codes in generated verified digital documents now encode an absolute /verify?record_id=... URL. Scanning the QR code opens a public verification page showing the verified document details.
- Officer verification immediately opens the generated digital document after status changes to Verified.
- Added MongoDB adapter support for admin lookup by user_id and land-record lookup by record_id used by OTP verification and QR verification.
- Reset command remains `npm run reset-db`; the execution environment used for this build has no MongoDB server listening on 127.0.0.1:27017, so the live database could not be cleared from this environment. Run `npm run reset-db` on the machine/Atlas database after MongoDB is reachable.
- Syntax checks passed for server.js, mongo-db.js, public/script.js and public/portal.js.
- Local HTTP smoke test: the server starts and serves the main page even when MongoDB is offline; database-backed endpoints correctly report database unavailability instead of crashing the Node process.
